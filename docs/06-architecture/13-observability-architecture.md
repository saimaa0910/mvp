## 01. Document Overview & Observability Philosophy
This document specifies the enterprise observability architecture, distributed tracing standards, Prometheus telemetry catalog, centralized logging pipelines, and Site Reliability Engineering (SRE) operational runbooks for the Namma Clinic Digital Health & Operations Platform. Spanning 183 distributed physical edge clinics and a multi-zone cloud control plane, the observability subsystem ensures end-to-end operational visibility, rapid root-cause isolation, and mathematical compliance with Service Level Objectives (SLOs).

### 01.1 Core Observability Invariants & Principles
1. **Vendor-Neutral OpenTelemetry Standard:** All application services, edge daemons, and client PWAs instrument telemetry using OpenTelemetry (OTel) SDKs, emitting standards-compliant traces, metrics, and logs.
2. **Universal Distributed Context Propagation:** Every user interaction mints a W3C `traceparent` header propagated across client PWAs, API gateways, internal gRPC calls, Kafka asynchronous queues, edge sync daemons, and database queries via SQL comment injection.
3. **Zero Plaintext PHI/PII in Telemetry:** All log messages, trace span attributes, and metric label values are automatically scrubbed of patient identifiers (Aadhaar, names, phone numbers, free-text clinical notes) before network emission.
4. **Multi-Tier Edge Fleet Telemetry:** Edge appliances report local health metrics (CPU, SSD wear, UPS battery, SQLite WAL size, mutation queue depth) via lightweight periodic telemetry pushes; alerting identifies degraded clinics before staff experience outages.
5. **Error Budget-Driven Alerting:** Alerts trigger on multi-window multi-burn-rate consumption of error budgets rather than noisy static threshold spikes, minimizing on-call alert fatigue.
6. **Cryptographic WORM Audit Mirroring:** All administrative actions and high-privilege configuration changes generate tamper-evident audit traces mirrored directly to the security vault.

## 02. OpenTelemetry (OTel) Distributed Tracing Architecture
Distributed tracing pipeline across edge and cloud environments:
```
 +--------------------------+                 +---------------------------+                 +--------------------------+
 |  Clinic Workstation PWA  | -- OTLP/HTTP -> |   Central OTel Collector  | -- Batch OTLP ->|   Tempo / Jaeger Trace   |
 |  (OpenTelemetry Web SDK) |   TraceContext  |   (Kubernetes DaemonSet)  |   gRPC Export   |   (Storage: S3 / NVMe)   |
 +--------------------------+                 +---------------------------+                 +--------------------------+
              |                                             ^                                             |
         Local Spans                                  Edge Spans                                     Trace Analysis
              v                                             |                                             v
 +--------------------------+                 +---------------------------+                 +--------------------------+
 |   Clinic Edge Daemon     | -- OTLP Sync -> |   Edge OTel Agent Proxy   |                 |    Grafana Trace View    |
 |   (SQLite WAL Spans)     |  Compressed mTLS|   (Local Mini-Server)     |                 |    (Correlated Logs)     |
 +--------------------------+                 +---------------------------+                 +--------------------------+
```

### 02.1 Context Propagation Specifications
- **W3C Trace Context Standard:** Every request MUST inject and extract `traceparent` (version, trace_id, parent_id, trace_flags) conforming to W3C recommendation.
- **W3C Baggage Header:** Mandatory baggage attributes include `namma.clinic_id`, `namma.ward_id`, `namma.staff_role`, and `namma.session_id`. Baggage MUST NOT contain patient names or national IDs.
- **SQL Comment Injection:** All database queries generated by Prisma or raw SQL clients MUST append sqlcommenter tags: `/*traceparent='00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01',route='/api/v1/patients'*/` allowing database engine query tracing.
- **Kafka Event Headers:** Asynchronous events published to Kafka brokers MUST inject W3C trace headers into Kafka RecordHeaders with keys `traceparent` and `tracestate`.

```typescript
      span.setAttribute('clinic.id', ctx.clinicId);
      span.setAttribute('staff.user_id', ctx.userId);
      span.setAttribute('staff.role', ctx.staffRole);
      span.setAttribute('net.peer.name', ctx.clientIp || '127.0.0.1');
      span.addEvent('operation.started', { timestamp: Date.now() });

      // Set span specific attributes
      span.setAttribute('sqlite.table', String(payload.table ?? 'UNKNOWN'));
      span.setAttribute('sqlite.wal_pages', String(payload.wal_pages ?? 'UNKNOWN'));
      span.setAttribute('sqlite.commit_ms', String(payload.commit_ms ?? 'UNKNOWN'));

      const result = await performDomainLogic(ctx, payload);

      const executionDuration = performance.now() - startTime;
      span.setAttribute('execution.duration_ms', executionDuration);
      span.addEvent('operation.completed', { status: 'SUCCESS', duration_ms: executionDuration });
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (err: any) {
      span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
      span.recordException(err);
      span.addEvent('operation.failed', {
        'error.name': err.name,
        'error.message': err.message,
        'error.timestamp': Date.now()
      });
      throw err;
    } finally {
      span.end();
    }
  }});
}
```

#### Span Lifecycle, Events & Sampling Directives:
1. **Context Propagation:** Injects W3C `traceparent` and `tracestate` into outbound gRPC/HTTP metadata and Kafka headers.
2. **Tail-Based Sampling:** Captured at 100% default rate; 100% of spans with errors (`status = ERROR`) or latency exceeding < 10ms are retained permanently in cold storage.
3. **Span Linkage:** Correlated with root HTTP ingress span and database transaction span via W3C SpanLink references.
4. **Telemetry Scrubbing:** Validated by pre-commit AST rules to guarantee no patient name or clinical free text is passed as a span attribute.

## 05. Production PrometheusRule Alerting Manifests
Standardized alerting groups deployed via Prometheus Operator to Kubernetes clusters:
```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: namma-platform-alerts
  namespace: monitoring
  labels:
    role: alert-rules
    app.kubernetes.io/part-of: namma-clinic
spec:
  groups:
  - name: namma.critical.alerts
    rules:
    - alert: MassClinicEdgeDisconnection
      expr: count(edge_clinic_online_status == 0) > 15
      for: 5m
      labels:
        severity: critical
        tier: edge-fleet
        team: sre-oncall
      annotations:
        summary: 'Mass clinic edge disconnection (> 15 clinics offline)'
        description: 'More than 15 Namma Clinics have lost cloud heartbeat simultaneously. Investigate municipal ISP backhaul or central ingress gateway.'
        runbook_url: 'https://ops.nammahealth.bbmp.gov.in/runbooks/SRE-RB-001'

    - alert: DatabaseConnectionPoolExhaustion
      expr: db_connection_pool_active / db_connection_pool_max > 0.88
      for: 3m
      labels:
        severity: critical
        tier: database
        team: dba-oncall
      annotations:
        summary: 'PgBouncer connection pool utilization exceeds 88%'
        description: 'PostgreSQL connection pool approaching exhaustion. Investigate connection leaks or slow queries locking tables.'
        runbook_url: 'https://ops.nammahealth.bbmp.gov.in/runbooks/SRE-RB-002'

    - alert: EmergencyCadDispatchFailureSpike
      expr: sum(rate(emergency_108_dispatches_total{status='FAILED'}[5m])) > 0
      for: 2m
      labels:
        severity: critical
        tier: integrations
        team: clinical-ops
      annotations:
        summary: '108 Ambulance CAD emergency dispatch integration failure'
        description: 'Emergency CAD dispatch requests to 108 Arogya Kavacha failed. Immediate voice escalation to GVK-EMRI control center required.'
        runbook_url: 'https://ops.nammahealth.bbmp.gov.in/runbooks/SRE-RB-003'

    - alert: TamperEvidentAuditChainCorruption
      expr: worm_audit_chain_verifications_total{status='tamper_detected'} > 0
      for: 1m
      labels:
        severity: critical
        tier: security
        team: secops-oncall
      annotations:
        summary: 'WORM audit ledger cryptographic hash chain verification failure'
        description: 'A cryptographic hash chain mismatch was detected in the immutable audit ledger. Potential unauthorized database tampering.'
        runbook_url: 'https://ops.nammahealth.bbmp.gov.in/runbooks/SRE-RB-004'

  - name: namma.clinical.alerts
    rules:
    - alert: MewsCriticalScoreCluster
      expr: sum(rate(mews_critical_alerts_total[1h])) > 25
      for: 10m
      labels:
        severity: high
        tier: clinical
        team: clinical-governance
      annotations:
        summary: 'Surge in critical MEWS triage alerts across clinics'
        description: 'Abnormal spike in MEWS scores >= 5 across multiple primary clinics. Investigate local infectious disease outbreak or heatwave event.'
        runbook_url: 'https://ops.nammahealth.bbmp.gov.in/runbooks/SRE-RB-005'

    - alert: PharmacyEssentialStockoutSpike
      expr: count(pharmacy_stockout_items > 5) > 10
      for: 30m
      labels:
        severity: high
```

### 07.2 In-Line PII Redaction Engine
Before logs exit any service process memory boundary, the logging formatter executes deterministic regex-based scrubbing:
1. **Aadhaar Masking:** Regex `\b[2-9][0-9]{3}[\s-]?[0-9]{4}[\s-]?[0-9]{4}\b` is replaced by `[REDACTED_AADHAAR]`.
2. **Phone Number Masking:** Regex `\b(?:\+91|91|0)?[6-9][0-9]{9}\b` is replaced by `[REDACTED_PHONE]`.
3. **ABHA ID Masking:** Regex `\b[0-9]{2}-[0-9]{4}-[0-9]{4}-[0-9]{4}\b` is replaced by `[REDACTED_ABHA]`.
4. **Free-Text Clinical Notes:** Free-text clinical observation strings are strictly prohibited from log arguments. AST linter rules reject code passing encounter notes to logger methods.

### 07.3 Log Storage, Indexing & Tiering Policy
| Tier | Storage Engine | Retention Window | Compression | Query SLA | Purpose |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **Hot Tier** | OpenSearch Cluster (NVMe) | 30 Days | Zstandard | < 1.0 sec | Real-time debugging, alerting, SRE triage |
| **Warm Tier** | S3 / Cloud Object Storage | 90 Days | Gzip Parquet | < 10.0 sec | Periodic reporting, compliance trend auditing |

## 11. Observability Architecture Fitness Tests & Verification Checklist
Automated CI/CD quality gates ensuring continuous compliance with observability standards:

### 11.1 Automated Architecture Fitness Tests
1. **Span Context Propagation Fitness Test:** Synthetic test fires an end-to-end HTTP request through API Gateway; asserts that child span ID and parent span ID match across all 18 service container boundaries.
2. **PII Leakage Regression Gate:** Injects synthetic Aadhaar and mobile numbers into test logging streams; asserts that regex scrubbing filter replaces them with `[REDACTED]` prior to emission.
3. **Prometheus Metric Schema Linter:** Validates that all newly instrumented Prometheus metrics conform to naming conventions (ending in `_total`, `_seconds`, `_bytes`) and strictly adhere to enumerated label dimensions.
4. **High-Cardinality Label Blocker:** Static analysis AST scanner fails pull requests if any metric label uses unbounded values (e.g., patient IDs, timestamps, session tokens).
5. **Distributed Trace Sampling Verification:** Tests that 100% of HTTP 500 error traces and slow traces (> 500ms) are retained by tail-sampling rules.
